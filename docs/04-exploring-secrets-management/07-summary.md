# Summary

In this section we have looked at various aspects of secrets management.
This includes the resource admins, resource groups and projects to
create and manage top-level secret folders. Then we looked at creating
policies to control who can manage folders and secrets within those
top-level folders. The policies defined groups of users who can manage
folders and secrets and those that can only view them. We used one of
the managers to create subfolders and secrets, then a user to view the
folders and secrets. We did not look at CLI or API access to secrets.

The next section looks at the Server Access use cases, which is
independent of this section.
